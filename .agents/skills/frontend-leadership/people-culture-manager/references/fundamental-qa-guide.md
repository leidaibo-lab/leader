## 1. 基础能力 (Fundamentals) - [Weight: 30%]
*(考察 JS/TS/CSS 基础，React/RN 原理，编码规范)*

### 1.1 JS/TS 核心 (必考)
*   **Q: (ES6+) `map`、`filter`、`reduce` 有什么区别？`forEach` 能 `break` 吗？**
    *   **参考答案**:
        *   **区别**: `map` 返回新数组；`filter` 返回过滤后的新数组；`reduce` 累加值。
        *   **中断**: `forEach` 无法通过 `break/return` 中断 (除非抛错)。想中断用 `for...of`。
    *   **评分标准**: ✅ 知道 `forEach` 不能中断；🌟 能熟练写出 `reduce` 实现对象数组去重。

*   **Q: (JSON 处理) 如何安全地解析一个可能格式错误的 JSON 字符串？**
    *   **参考答案**:
        *   **Try-Catch**: 必须用 `try { JSON.parse(str) } catch (e) { ... }` 包裹。
        *   **防御**: 后端返回空字符串或 undefined 时要特判。
    *   **评分标准**: ✅ 知道 JSON.parse 会报错，必须 try-catch；🌟 提到 `JSON.stringify` 会过滤 undefined 属性。

*   **Q: (ES6+) 箭头函数和普通函数有什么区别？**
    *   **参考答案**:
        *   **this**: 箭头函数没有自己的 `this`，继承上层作用域；普通函数看调用方式。
        *   **构造**: 箭头函数不能 `new` (没有 prototype)。
        *   **arguments**: 箭头函数没有 `arguments` 对象。
    *   **评分标准**: ✅ 知道 this 指向区别；🌟 提到不能用作构造函数。

*   **Q: (CSS 基础) 怎么实现一个盒子水平垂直居中？(至少说出 2 种)**
    *   **参考答案**:
        1.  **Flexbox**: `display: flex; justify-content: center; align-items: center;` (最推荐)。
        2.  **Grid**: `display: grid; place-items: center;`。
        3.  **定位**: `absolute` + `transform: translate(-50%, -50%)`。
    *   **评分标准**: ✅ 能手写 Flex 布局代码；🌟 知道 Grid 的简写属性。

*   **Q: (CSS 基础) 什么是盒模型？`box-sizing: border-box` 有什么用？**
    *   **参考答案**:
        *   **标准模型**: `width` = 内容宽度 (不含 padding/border)。
        *   **IE/怪异模型**: `width` = 内容 + padding + border。
        *   **border-box**: 让元素走怪异模型，设置的 `width` 就是最终占用的宽度，方便布局。
    *   **评分标准**: ✅ 知道 border-box 更易于布局；🌟 能解释标准模型的计算公式。

*   **Q: 什么是闭包？在实际开发中哪儿用到了？Hooks 中的“闭包陷阱”是怎么回事？**
    *   **参考答案**:
        *   **定义**: 函数嵌套函数，内部引用外部变量。
        *   **场景**: 防抖/节流、模块封装、React Hooks (useEffect)。
        *   **陷阱**: `useEffect` 依赖项为空 `[]` 时，内部回调捕获了旧的 `state` 值。解决方法：加依赖项、函数式更新、`useRef`。
    *   **评分标准**: ✅ 能说出定义和 Hooks 场景；🌟 能解释 Stale Closure 成因。

*   **Q: EventLoop 中宏任务与微任务的区别？`await` 后面的代码是在什么时候执行？**
    *   **参考答案**:
        *   **顺序**: 同步 -> 微任务 (Promise, MutationObserver) -> 渲染 -> 宏任务 (setTimeout)。
        *   **await**: `await` 这一行是同步的，后面的代码相当于放进 `Promise.then` (微任务) 中。
    *   **评分标准**: ✅ 知道微任务优先；🌟 能分析 async/await 执行顺序。

*   **Q: (TS 场景题) 假设后端接口返回的字段经常变，你怎么处理？在定义组件 Props 时，什么情况下会用到泛型（比如 List 组件）？**
    *   **参考答案**:
        *   **接口不稳定**: 用 `?` (Optional) 标记可选字段，或者用 `Partial<Type>`。代码里多用 `?.` (Optional Chaining) 防止报错。
        *   **泛型组件**: 举例：一个通用的 List 组件，既能渲染“用户列表”，也能渲染“商品列表”。用 `<T>` 可以让 List 自动识别传进来的是 User 还是 Product，不需要手动强制转换类型。
    *   **评分标准**: ✅ 知道用 `?` 和 `?.` 处理空值；🌟 能解释泛型是为了复用组件逻辑。

*   **Q: (TS 场景题) 如果调用一个返回 Promise 的异步接口，你怎么定义它的返回类型？如何处理 API 可能返回的 Error？**
    *   **参考答案**:
        *   **类型定义**: 使用 `Promise<ApiResponse<Data>>`。
        *   **错误处理**: `try-catch` 包裹 `await`，或者使用 `.catch()`。
        *   **高级**: 定义一个通用的 `Result<T, E>` 类型来统一成功和失败的结构。
    *   **评分标准**: ✅ 知道 Promise 是泛型；🌟 提到统一的错误处理结构。

### 1.2 React/RN 原理 (必考 - 递进式发问)
> **建议**: 针对一个知识点，从浅入深追问 3 层，直到候选人卡住，测出其技术天花板。

*   **话题: React 渲染原理 (从 Key 到 Fiber 的演进)**
    *   **Level 1 (基础)**: "列表渲染为什么要加 `key`？"
        *   *期望*: 知道 key 是 Diff 算法复用 DOM 的唯一标识。
    *   **Level 2 (进阶)**: "React 的 Diff 算法是怎么工作的？它是怎么比较两棵树的？"
        *   *期望*: 提到 **同层比较 (Level-by-Level)**。React 假设如果两个组件类型不同，产生的新树也完全不同。
    *   **Level 3 (原理)**: "为什么 React 16 之后要引入 Fiber 架构？它解决了什么痛点？"
        *   *期望*: 提到 **可中断渲染 (Time Slicing)**。
            *   *新架构 (Fiber)*: 把渲染任务切片，分成很多小任务。每执行完一小片，就看看浏览器有没有更高优先级的任务 (如用户输入)，如果有就先让路。
    *   **Level 4 (深水区)**: "既然可以中断，那 React 是怎么保证页面不会渲染一半的？"
        *   *期望*: 提到 **双缓存机制 (Double Buffering)**。Fiber 树分 `current` (当前屏幕显示) 和 `workInProgress` (正在构建)。所有更新都在内存中的 `workInProgress` 树上进行，构建完成后，一次性切换指针 (commit)，用户看到的画面是瞬间完成的。
    *   **Level 5 (源码级)**: "React 是怎么实现时间切片 (Time Slicing) 的？浏览器并没有适配这个 API 呀？"
        *   *期望*:
            *   **Scheduler (调度器)**: React 自己实现了一个调度器。
            *   **MessageChannel**: 利用宏任务 (MessageChannel) 来模拟 `requestIdleCallback` (因为原生 API 不稳定且兼容性差)。
            *   **机制**: 在每一帧的空闲时间 (5ms 左右)，执行 Fiber 工作单元。如果时间到了，就 `yield` 出去，让浏览器响应用户输入，然后通过 `postMessage` 通知自己下一帧继续干活。

*   **话题: React Native 跨端原理 (针对 RN 候选人)**
    *   **Level 1 (基础)**: "RN 和 Web 开发最大的区别是什么？"
        *   *期望*: 标签不同 (View vs div)，样式不同 (Flexbox only)。
    *   **Level 2 (原理)**: "JS 写的代码是怎么在手机上跑起来的？它是怎么变成原生 UI 的？"
        *   *期望*: 提到 **Bridge (桥接)** 概念。JS 线程发送 JSON 消息给 UI 线程，原生端解析 JSON 并渲染原生 View。
    *   **Level 3 (性能)**: "你知道 RN 的新架构 (Fabric/TurboModule) 解决了什么问题吗？"
        *   *期望*: 解决了 Bridge 的异步通信瓶颈，实现了 JSI (同步调用)，让 JS 可以直接控制原生 UI，提升滚动/手势性能。

### 1.3 场景化思维 (Practical Scenarios)
> **原则**: 只需要候选人描述思路和关键点，**不需要手写代码，也不需要伪代码**。重点考察思维逻辑和边界意识。

*   **场景 A: 搜索框防抖设计**
    *   **面试官提问**: "假设你在做一个搜索框，用户输入时实时调用接口。为了防止接口调太频繁，你会怎么优化？如果这个组件被用户快速切换（卸载）了，你的防抖逻辑会有什么问题吗？"
    *   **期望回答**:
        *   **思路**: 提到 Debounce (防抖) 策略。
        *   **边界**: 能意识到组件卸载时，如果定时器还在跑，可能会报错 (Can't perform state update on unmounted component) 或内存泄漏。需要**清除定时器**。

*   **场景 B: 批量请求并发控制**
    *   **面试官提问**: "如果现在要同时下载 100 张图片，浏览器或者服务器可能会扛不住。你怎么控制一下，让它每次最多只下载 3 张？描述一下你的实现逻辑。"
    *   **期望回答**:
        *   **思路**: 维护一个“正在执行”的任务池。
        *   **调度**: 启动 3 个任务 -> 哪一个完成了，就立马塞进去一个新的 -> 直到全部完成。而不是简单的“3个3个一组” (那是分批，效率不如并发控制)。

*   **场景 C: 缓存淘汰策略 (LRU)**
    *   **面试官提问**: "浏览器的缓存或者 Vue 的 `keep-alive` 都有个最大数量限制。如果让你设计一个定长缓存（比如最多存 10 个），**最近访问的自动排到最前面，满了自动删最旧的**。只描述思路，怎么做效率最高？"
    *   **期望回答**:
        *   **数据结构**: 提到 **Map** (JS Map 也是有序的) 或者 **双向链表 + 哈希表**。
        *   **逻辑**:
            *   *访问时*: 如果存在，先删掉，再 set 进去 (JS Map 会自动排到最后)。
            *   *新增时*: 如果满了，删除第一个 (`map.keys().next().value`)，再 set 新的。
    *   **评分标准**: ✅ 能想到 Map 是有序的；🌟 能解释为什么用 Map (O(1)) 比用 Array (O(n)) 快。

## 2. 工程化与架构 (Engineering & Architecture) - [Weight: 30%]
*(考察 构建工具、性能优化、组件设计、状态管理、模块化)*

### 2.1 构建与基建 (实战优化)
*   **Q: (实战) 你的项目构建慢吗？你是怎么优化的？(不限 Webpack/Vite)**
    *   **Level 1 (Webpack 优化)**: "如果用 Webpack，怎么提升构建速度？"
        *   *期望*: 提到 **Loader 缓存** (cache-loader)、**多线程** (thread-loader)、**缩小构建范围** (include/exclude)、**DllPlugin** (预编译)。
    *   **Level 2 (Vite 优化)**: "Vite 开发环境虽然快，但生产打包（Rollup）慢怎么办？"
        *   *期望*: 提到 **拆包策略** (manualChunks)、**压缩插件** (vite-plugin-compression)、**按需引入** (unplugin-vue-components/Antd)。
    *   **Level 3 (对比差异)**: "你觉得 Vite 和 Webpack 最大的体感差异是什么？什么情况下你会坚守 Webpack？"
        *   *期望*:
            *   **差异**: Vite 启动秒开，HMR 极快；Webpack 配置繁琐但生态最全。
            *   **坚守 Webpack**: 需要复杂的 SplitChunks 策略、微前端 (Module Federation) 支持更成熟、老项目迁移成本高。
    *   **评分标准**: ✅ 能说出至少 2 种具体优化手段；🌟 有实际对比经验，而非背八股文。

*   **Q: 如何统一团队的代码规范？提交时如何拦截不合规代码？**
    *   **参考答案**:
        *   **工具**: ESLint + Prettier。
        *   **流程**: Husky (Git Hooks) + Lint-staged (只检查暂存区) + Commitlint。
    *   **评分标准**: ✅ 提到 Husky/Lint-staged；🌟 提到 CI 流水线检查。

### 2.2 性能优化 (递进式发问)
*   **话题: 页面加载性能优化**
    *   **Level 1 (基础)**: "用户反馈页面白屏时间长，你会怎么优化？"
        *   *期望*: 路由懒加载、图片压缩、CDN、Gzip。
    *   **Level 2 (进阶)**: "怎么定位是网络慢还是代码执行慢？你会看哪些指标？"
        *   *期望*: 提到 **FCP (首屏)**、**LCP (最大内容)**、**TTI (可交互)**。会用 Chrome Network 和 Performance 面板。
    *   **Level 3 (实战)**: "如果 Network 很快，但 JS 执行时间太长导致卡顿 (Long Task)，怎么拆分任务？"
        *   *期望*: 提到 **Web Worker** (多线程)、**requestIdleCallback** (空闲执行) 或 React 的 `Suspense` / `useTransition`。

## 3. 业务理解与解决问题 (Business & Problem Solving) - [Weight: 20%]
*(考察 业务场景落地、难点攻克、方案权衡)*

### 3.1 难点攻克 (STAR 法则发问)
*   **Q: 介绍一个你最自豪的项目。难点在哪？为什么这么设计？**
    *   **Level 1 (Situation/Task)**: "当时的业务背景是什么？为什么要解决这个问题？"

*   **Q: (系统设计) 如何设计一个高可用的 B 端权限系统 (RBAC)？**
    *   **Level 1 (功能)**: "菜单、按钮、接口权限分别怎么控制？"

## 4. 软技能与潜力 (Soft Skills & Potential) - [Weight: 20%]
