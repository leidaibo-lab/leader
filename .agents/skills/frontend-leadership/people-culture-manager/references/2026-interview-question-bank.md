# 2026 前端团队扩充：核心人才面试题库与考察指南 (React Focus, RN Bonus)

## 目录

- 技术标杆
- 工程化专家
- 业务闭环负责人
- 文化布道者
- 职级差异化考察矩阵
- 综合评估表

本指南用于辅助面试官精准识别四类关键人才：**技术标杆 (The Bar Raiser)**、**工程化专家 (The Force Multiplier)**、**业务闭环负责人 (The Business Owner)**、**文化布道者 (The Culture Carrier)**。

**背景**：
*   **核心技术栈**: React (Web)
*   **扩展技术栈**: React Native (Mobile) —— **作为加分项 (Bonus)，非强制要求**。
*   **现状**: 基础建设（组件库、工具库、CLI、规范）已初步完成。
*   **目标**: 夯实 Web 基础，探索多端一致性，关注基建落地与性能深挖。
*   **职级体系**: P2 (初级) | P3-1/2/3 (中级) | P4 (高级)。

---

## 1. 考察「技术标杆」 (The Bar Raiser)
**目标**：识别其在 React 领域的深度，能否解决“深水区”的技术难题。RN 能力作为加分项考察。

### 核心问题 (React 深度 - 必考)
*   **Q1 (Hook 原理): "React Hooks 的闭包陷阱 (Stale Closure) 是怎么产生的？你在实际项目中遇到过吗？除了加依赖项，还有什么更优雅的解决办法（如 useLatest 或 Ref）？"**
    *   *考察点*：相比于抽象的并发模式，这个问题更考察对 JS 闭包和 React 渲染机制的理解，且非常贴合业务开发痛点。
*   **Q2 (性能优化): "如果一个复杂的 Dashboard 页面操作卡顿，你会从哪些指标入手分析？如何使用 Chrome DevTools 的 Performance 面板定位长任务 (Long Task)？"**
    *   *考察点*：是否精通浏览器渲染原理（重排/重绘）？是否懂得 React.memo / useMemo 的正确使用场景（避免过度优化）？
*   **Q3 (架构设计): "面对一个巨型单页应用 (SPA)，随着代码量增加，首屏越来越慢。你会采用哪些架构手段来拆分？"**
    *   *考察点*：代码分割 (Code Splitting)、微前端 (Micro-frontend)、模块联邦 (Module Federation) 的选型与落地。

### 进阶/加分问题 (React Native - 选考)
*   **Q4 (跨端思维): "如果你用过 React Native，你觉得它和 Web 开发最大的思维差异是什么？"**
    *   *考察点*：是否了解 Native 线程模型？是否知道 Flexbox 在 RN 上的差异？(有则加分，无则不扣分)

### 信号识别
*   ✅ **通过信号**：能手写 Hooks 原理；精通 Chrome DevTools；对 React 源码有一定了解。
*   🌟 **加分信号**：有 RN 实战经验；懂 Native (iOS/Android) 桥接细节。
*   ❌ **警惕信号**：只会用 useEffect；不懂闭包陷阱；无法解释 Virtual DOM 的价值。

## 2. 考察「工程化专家」 (The Force Multiplier)
**目标**：在基建“已完成”的背景下，识别其**推广落地**、**版本治理**和**效能提升**的能力。

### 核心问题 (基建落地与演进 - 必考)
*   **Q1 (基建推广): "我们的脚手架和组件库已经开发好了，但业务线同学还在用老的一套，或者经常魔改组件。你会怎么推动他们升级？"**
    *   *考察点*：是否具备软技能（推广策略）？是否懂得用技术手段（如 Codemod 自动迁移脚本）降低升级成本？
*   **Q2 (构建效率): "随着项目变大，Webpack 构建速度越来越慢。如果让你把构建工具迁移到 Vite 或 Rspack，你会考虑哪些兼容性问题？"**
    *   *考察点*：对构建工具底层（Loader/Plugin）的理解。是否具备大型项目迁移经验？
*   **Q3 (代码质量): "如何通过 CI/CD 流程强制拦截不合规的代码（如类型错误、循环依赖、大文件提交）？"**
    *   *考察点*：熟悉 Husky, Lint-staged, SonarQube 等工具链的集成与配置。

### 进阶/加分问题 (Mobile DevOps - 选考)
*   **Q4 (移动端发布): "你有过配置 RN 或 App 自动化构建（如 Fastlane）的经验吗？"**
    *   *考察点*：是否了解移动端特有的签名、证书、Store 审核流程。(有则大幅加分)

### 信号识别
*   ✅ **通过信号**：提到 "Codemod/AST"（自动化重构）；熟悉 Monorepo (Nx/Turborepo) 管理策略；有大型项目构建优化经验。
*   🌟 **加分信号**：有 App 自动化发布经验；熟悉 Docker/K8s 容器化部署。
*   ❌ **警惕信号**：只管造轮子不管修轮子；认为“推广是行政命令”；配置 Webpack 只会 Copy-Paste。

## 3. 考察「业务闭环负责人」 (The Business Owner)
**目标**：识别其在复杂业务场景下的 ROI 思维与交付能力。

### 核心问题 (业务思维 - 必考)
*   **Q1 (数据驱动): "上线了一个新功能，用户反馈‘体验不好’。你会看哪些监控指标来量化这个‘不好’？"**
    *   *考察点*：全链路排查能力。是否会用 Sentry/Datadog？关注 FCP, LCP, CLS 等 Web Vitals 指标。
*   **Q2 (复杂业务): "当业务需求非常复杂，导致代码逻辑变得很难维护（比如一个几千行的组件）。你在不重写的前提下，通常怎么做局部重构？"**
    *   *考察点*：相比于宏大的选型，这个问题更考察实际的“代码治理”能力。是否会提取 Hook？是否会拆分 Presentational/Container 组件？
*   **Q3 (项目管理): "业务需求变更频繁，导致代码充斥着大量的 `if-else` 和临时补丁。作为 TL，你如何在保证交付的前提下进行重构？"**
    *   *考察点*：技术债务管理。是否懂得“小步快跑”的重构策略？

### 进阶/加分问题 (多端体验 - 选考)
*   **Q4 (多端一致性): "如果这个功能同时要在 Web 和 App 上线，你会如何规划开发节奏？"**
    *   *考察点*：是否具备多端协同的意识？(有则加分)

### 信号识别
*   ✅ **通过信号**：言必称“价值/数据”；能主动思考产品逻辑；有带领小团队（3-5人）的经验。
*   🌟 **加分信号**：有跨端产品（Web + App）的交付经验；懂端侧埋点策略。
*   ❌ **警惕信号**：只把自己当“资源”；不关注上线后的数据；遇到问题推给 PM。

## 4. 考察「文化布道者」 (The Culture Carrier)
**目标**：识别其职业素养、影响力及导师潜质。

### 核心问题 (行为面试 - 必考)
*   **Q1 (知识沉淀): "你最近解决的一个比较难的技术问题是什么？解决后你有沉淀成文档或者分享给团队吗？（如果有，请展示一下）"**
    *   *考察点*：相比于强制别人写 TS，这个问题更考察候选人**自身的分享习惯**。通过具体的文档质量，能看出他的逻辑性和利他精神。
*   **Q2: "请分享一次你搞砸了的经历（如线上故障）。你是如何处理的？事后做了什么？"**
    *   *考察点*：诚实度与责任感。是推诿责任还是深刻复盘？是否有改进措施防止再犯？
*   **Q3: "如果团队里有个新人成长很慢，你会怎么帮助他？"**
    *   *考察点*：导师意识 (Mentorship)。是否有耐心？是否懂得因材施教？

### 信号识别
*   ✅ **通过信号**：正能量；乐于分享（博客/演讲）；具备同理心；关注他人成长。
*   ❌ **警惕信号**：抱怨前公司/同事；固执己见；缺乏反思能力。

## 5. 职级差异化考察矩阵 (Leveling Matrix: P2-P4)

针对公司内部职级体系（P2-P4），制定差异化考察标准。

| 维度 | **P2 初级 (Junior)** | **P3-1/2/3 中级 (Senior)** | **P4 高级 (Staff/Lead)** |
| :--- | :--- | :--- | :--- |
| **技术标杆** | **关注基础**：<br>JS/CSS 基础扎实，熟练使用 React Hooks。<br>_Q: "useEffect 依赖项怎么填？闭包陷阱怎么解？"_ | **关注深度与场景**：<br>懂 React 原理，能解决复杂业务场景的性能瓶颈。<br>_Q: "如何定位长列表卡顿？Context 性能怎么优化？"_ | **关注架构与前瞻**：<br>具备全局视野，能做技术规划与选型。<br>_Q: "微前端架构怎么落地？如何设计高可用的基建？"_ |
| **工程化专家** | **关注执行**：<br>遵守规范，不提交 AnyScript，熟练解决 Git 冲突。<br>_Q: "你平时怎么管理分支？"_ | **关注工具建设**：<br>能开发 Webpack/Vite 插件，维护私有 npm 包。<br>_Q: "如何通过脚手架统一项目模板？"_ | **关注体系演进**：<br>Monorepo 治理，构建效率翻倍，推动基建落地。<br>_Q: "如何设计一套支持 50+ 业务组件的文档系统？"_ |
| **业务闭环** | **关注交付**：<br>按 UI 稿还原页面，按时交付。<br>_Q: "遇到设计稿不合理怎么沟通？"_ | **关注模块负责**：<br>独立负责一个复杂模块，能做局部重构。<br>_Q: "如何拆分一个 3000 行的巨型组件？"_ | **关注业务价值**：<br>技术反哺业务，提升转化率，全渠道体验一致性。<br>_Q: "如何通过技术手段提升用户留存？"_ |
| **文化布道** | **关注学习**：<br>好奇心强，关注 React 社区动态。<br>_Q: "最近学了什么新技术？"_ | **关注沉淀**：<br>产出高质量文档，做内部分享。<br>_Q: "请展示一篇你写的技术复盘文档。 / 怎么带新人？"_ | **关注影响力**：<br>定义工程师文化，解决团队内耗，凝聚人心。<br>_Q: "如何处理团队内的技术分歧？"_ |

> **注**：React Native 相关能力在各职级均作为 **加分项**，不作为硬性门槛。对于 P4 候选人，若具备 RN 架构经验，可视为 Strong Hire 信号。

## 6. 综合评估表 (Scorecard Template)

建议为每位候选人建立评分卡，维度如下：

| 维度 | 权重 | 评分 (1-5) | 核心考察点 |
| :--- | :--- | :--- | :--- |
| **React Web 深度** | 30% | | 源码理解、性能优化、架构设计 |
| **工程化/基建** | 20% | | 构建工具、DevOps、基建推广能力 |
| **业务思维** | 20% | | 价值导向、沟通协作、项目管理 |
| **文化匹配度** | 20% | | 影响力、分享意愿、Mentorship |
| **加分项 (Bonus)** | 10% | | **React Native**、Node.js、图形学等 |

**决策建议**：
*   **Strong Hire**: 某一项达到 5 分（标杆），且无明显短板（< 3 分）。**若有 RN 经验，优先录取。**
*   **Hire**: 综合平均分 > 4 分。
*   **No Hire**: 存在一项 < 2 分（硬伤），或平庸（全 3 分）。
