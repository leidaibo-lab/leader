## 一、 招聘全流程概览 (Process Overview)

西舟鲤科技（深圳）的招聘流程遵循从需求发起、渠道拓展、筛选面试到最终录用的标准化路径。

### 1.1 核心阶段与关键动作

| 阶段 | 核心动作 | 责任方/角色 |
| :--- | :--- | :--- |
| **1. 简历筛选** | 评估简历匹配度；筛选出符合基本要求的候选人 | TL、面试官 (白永亮、陈冬等) |
| **2. 面试安排与执行** | HR协调时间/地点（线下）；面试官准备题目与考察点；执行面试 | HR、行政、面试官 |
| **3. 面试评估与决策** | 面试官内部评估打分；录用或进入下一轮 (24h内反馈) | 面试官团队、部门负责人 |
| **4. Offer与入职** | 飞书群跟进Offer发放及入职时间 | HR、部门负责人 |

### 1.2 简历筛选建议 (Screening Criteria)
*   **初级前端 (P2/P3-1)**：3年左右 + 基础扎实 + 1个完整React项目 + 掌握 TS。
*   **中级前端 (P3-2/P3-3)**：4年左右 + 多项目经验 + 原理理解 + 性能优化案例。
*   **高级前端 (P4)**：5年左右 + 基础库搭建 + 全链路优化 + 影响力。
*   **资深前端 (P5)**：6年左右 + 架构设计 + 团队管理。

### 1.3 协作机制
*   **内推激励**：鼓励全员内推，入职转正有现金奖励。
*   **团队协作**：技术负责人 (雷代波) 与面试官团队 (朱击潞、黄广明、白永亮等) 共同筛选。
*   **练手与复盘**：利用部分机会锻炼新晋面试官，并定期复盘优化流程。

## 二、 面试内容与考察维度 (Content & Dimensions)

### 2.1 核心考察维度

| 考察维度 | 具体内容/示例 |
| :--- | :--- |
| **工作经验** | 年限 (3-7年)；角色 (主力开发/小组长)。 |
| **技术基础** | JS核心 (闭包/原型链/EventLoop/Promise)；浏览器渲染原理；HTML/CSS。 |
| **技术栈** | **React生态** (原理/Redux/Hooks)；Vue生态；**TypeScript**；跨端 (RN/Taro)。 |
| **工程能力** | Webpack/Vite配置；性能优化 (渲染/加载)；代码规范；微前端/Monorepo。 |
| **项目经验** | 技术选型决策；难点攻克方案；B端/供应链业务理解。 |
| **个人特质** | 沟通协作；学习热情；**AI应用理解**；稳定性。 |

### 2.2 面试形式
*   **笔试环节**：针对大部分候选人，考察基础编码能力 (约10题)。*优秀者或时间紧迫可由面试官决定免笔试。*
*   **技术面试**：深挖技术深度、项目细节、解决思路。
*   **综合评估**：考察团队协作、文化适配。
*   **记录复盘**：鼓励录音/录屏 (需告知候选人)，便于同步信息。

## 四、 行动指南 (Action Guide)

### 4.1 HR / 行政
1.  **准备**: 提前一天预约会议室，准备水/纸笔。
2.  **安排**: 尽量安排在 **9:30-11:00** 或 **13:30-17:30**。同半天最多 2 位候选人。
3.  **签到**: 引导候选人填写签到表 (`https://w74x12qb16.feishu.cn/share/base/form/shrcn4C7kINDUbvy6dRIKtiy7Fg`)。
4.  **同步**: 简历提前给到面试官，群内同步状态。

### 4.2 面试官 (Interviewer)
1.  **提前准备**:
    *   **必做**: 提前看简历，找出技术亮点，准备针对性题目。
    *   **确认**: 清楚岗位职级 (P3/P4?) 和所属团队技术栈。
2.  **面试执行**:
    *   **形象**: 坐姿端正，情绪可控，尊重候选人。
    *   **流程**: 自我介绍 -> 基础知识 -> 项目深挖 -> 反问环节。
    *   **笔试**: 默认进行。如候选人优秀或时间紧，可免试 (需备注)。
3.  **决策与反馈**:
    *   **通过**: 明确推给谁 (下一轮面试官)。
    *   **不通过**: 礼貌引导离开，清理桌面 (水杯/垃圾)。
    *   **记录**: 及时在系统/群内填写面评，关注 **基础能力、项目经验、技术契合度**。

## 五、 决策建议标准 (Decision Criteria)

1.  **基础能力**：中等及以上，能满足开发需求。
2.  **项目经验**：核心成员或有 0-1 经验优先；有管理经验加分。
3.  **技术栈**：熟练 React/Vue；有 **Taro/React Native** 经验加分。
4.  **工程化**：熟悉构建流程，有搭建经验。
5.  **AI 实践能力** (Must Have)：**必须有 AI 辅助开发实践**。能直接使用 Cursor/Trae/Copilot 等工具融入当前开发流，**拒绝零基础需培训**的人员。
6.  **沟通能力**：表达顺畅，逻辑清晰。
7.  **契合度**：技术方向 (React/RN) 与团队规划高度一致。

## 六、 附录：核心人才面试题库 (Interview Question Bank)

> 本题库用于辅助识别关键人才，考察重点：**React 深度**、**工程化落地**、**AI 实践**、**业务闭环**。

### 6.1 React 核心与深度 (必考)
*   **Hook 原理与闭包陷阱**: "React Hooks 的闭包陷阱 (Stale Closure) 是怎么产生的？除了加依赖项，还有什么解决办法 (useLatest/Ref)？"
*   **性能优化实战**: "如果复杂页面卡顿，如何用 Chrome Performance 面板定位 Long Task？React.memo/useMemo 的正确使用场景？"
*   **架构设计 (P4+)**: "面对巨型 SPA，首屏越来越慢，你会采用哪些手段拆分？(Code Splitting / 微前端 / Module Federation)"
*   *加分项*: **跨端思维**: "React Native 和 Web 开发最大的思维差异是什么？(线程模型/布局差异)"

### 6.2 工程化与基建 (中高级必考)
*   **基建推广**: "如果业务线还在用老组件或魔改组件，你如何推动脚手架和组件库的升级落地？(Codemod/沟通策略)"
*   **构建优化**: "随着项目变大，Webpack 构建变慢，如何优化？如果迁移 Vite/Rspack 会遇到什么兼容性问题？"
*   **质量守门**: "如何通过 CI/CD (Husky/Lint-staged) 强制拦截不合规代码？"
*   *加分项*: **移动端发布**: "是否有配置 RN/App 自动化构建 (Fastlane) 的经验？"

### 6.3 AI 实践能力 (Must Have - 必考)
> **目标**: 验证候选人是否已将 AI 融入日常工作流，能否“即插即用”。
*   **场景实操**: "在日常开发中，你最常用的 AI Prompt (提示词) 是什么？请举一个你用 AI 解决具体 Bug 或生成复杂代码的例子。"
*   **工具认知**: "你用过 Cursor/Copilot 吗？你觉得它们在重构代码或写单元测试时，有什么局限性？你是怎么人工干预的？"
*   **提效案例**: "有没有利用 AI 快速学习新框架或生成文档的经历？效率提升了多少？"
*   *❌ 警惕信号*: 认为 AI 只是玩具、完全没用过、或者只会问简单的“这是什么”。

### 6.4 业务思维与团队文化 (Culture & Proactivity)
*   **自驱与活跃度**: "除了完成业务需求，你最近主动为团队或项目做过什么改进？(如优化工具、整理文档、主动修复线上陈旧 Bug)" —— *识别是否是活跃分子*。
*   **知识沉淀**: "最近解决的一个难点是什么？是否有沉淀文档或分享？(考察利他精神与总结习惯)"
*   **数据驱动**: "上线新功能后，用户反馈体验不好，你会看哪些监控指标 (FCP/LCP/Error Rate) 来量化？"
*   **代码治理**: "面对几千行的遗留复杂组件，不重写的前提下，如何做局部重构和拆分？"
*   **故障复盘**: "分享一次搞砸的经历，你是如何处理和复盘的？(考察责任感与抗压性)"
*   **团队协作**: "当项目 Deadline 临近，但你的模块已完成，你会怎么做？(考察团队意识)"

## 七、 活跃度与文化契合度考察 (The Proactivity Test)

我们不仅需要技术好的，更需要**“能折腾、有活力”**的队友。

### 7.1 活跃分子的特征 (Signals of Proactivity)
*   **眼里有活**：能主动发现现有基建/流程的痛点并提出方案。
*   **乐于分享**：在面试中能滔滔不绝讲清楚自己钻研的技术，且有输出（博客/GitHub/内部分享）。
*   **积极回应**：面试交流中反馈积极，思维活跃，而非“问一句答一句”。

### 7.2 核心行为面试题 (STAR Method)
1.  **关于自驱**：“请分享一个你**自发发起**并落地的技术改进项。背景是什么？你遇到了什么阻力？最终结果如何？”
2.  **关于热情**：“最近半年，你除了工作内容，额外钻研最深的技术是什么？为什么对它感兴趣？”
3.  **关于影响力**：“如果你发现团队内有些代码写得很烂，你会怎么做？(考察沟通方式与改变现状的欲望)”

### 7.3 一票否决项 (Culture Red Flags)
*   **推诿扯皮**：言语中充满对前公司、产品经理或同事的抱怨。
*   **极度被动**：只做被指派的任务，对技术演进完全不关心。
*   **沟通黑洞**：表达极其简短，不愿交流思路，拒绝协作。
