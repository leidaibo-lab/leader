# 前端团队职级能力与定级标准（宪法版）

> **本文档为前端团队人员招聘定级、绩效评估与晋升答辩的唯一准则。**
> **核心原则**：防自嗨、拒虚词、卡底线。所有职级评定均以“量化战功”、“硬性红线”和“排障复杂度”为依据，彻底剥离“了解、熟悉、精通”等模糊表述。

---

## P2：初级（生产级交付节点）
**【晋升预期：0-1 年】**
**核心底线：产出的代码具备工业级稳定性，绝不向 UI 层泄漏脏数据，且具备基础的职业素养。**

### 1. 技术与架构深度
*   **强类型防御**：能写出严谨的 TypeScript 泛型推导，绝不容忍 `any`、隐式类型或对象层级的野蛮探测。
*   **边界与收敛**：面对交互，必须前置梳理状态机。绝对不允许在渲染层散落多重 `if/else` 嵌套逻辑。
*   **数据清洗网关**：必须在 API 响应层完成数据的清洗、默认值降级与格式化，确保流入视图层的 Props 绝对安全且纯粹。
*   **现代工具链运用**：熟练掌握 Git 协作流（Rebase、Cherry-pick 等），理解 Webpack/Vite 的基础打包机制。

### 2. 复杂问题解决
*   **运行时崩溃归零**：交付的模块在极端边界下（断网、核心字段缺失、连点并发）必须具备完备的降级或容错机制。
*   **独立排错能力**：能够脱离业务表面，直接通过浏览器底层行为（如 Network 时序、Call Tree、Source Map）排查请求积压或运行时错误，而不是只会 `console.log`。

### 3. 协作与软素质（硬性要求）
*   **事事有回音**：遇到技术阻碍（如接口调不通、依赖包装不上），超过 2 小时未解决必须主动抛出并在群内同步上下文，绝不允许在站会或联调 DDL 时才爆出雷点。
*   **契约精神**：需求评审后，必须主动和后端对齐 JSON 契约并落地 Mock，绝不接受“后端接口没好所以我没法开发”的借口。

### ❌ 淘汰红线（Anti-patterns）
*   **黑盒交付**：提测前不自测主流程（导致 QA 发现点不动、白屏），直接扣绩效。
*   **魔法代码**：代码里出现未定义的“魔法数字/字符串”，或提交未去除的 `console.log`、遗留警告。
*   **AI 依赖失控**：使用 AI 生成的代码，在 Code Review 被问及逻辑或边界时答不上来（“这是工具写的”），直接打回。

## P3：中级（领域闭环与重构捍卫者）
**【晋升预期：P3 内部 2-3 年】**
**核心底线：不仅要完成业务需求，必须有能力把控中大型模块的状态流转，并清剿前人留下的技术债。**

### 1. 技术与架构深度（分层级递进）
*   **【P3-1】状态机设计**：独立设计并落地复杂业务（如多维表单、复杂大盘可视化）的状态管理流。能精确控制 Hooks 的依赖与渲染粒度，杜绝数据竞争或闭包陷阱。
*   **【P3-2】性能护城河**：突破“能跑就行”。交付的核心链路必须自带性能保障（FCP/LCP 达标）。能实施细粒度的代码分割（Code Splitting）、资源预加载与缓存策略。
*   **【P3-3】跨业务线抽象**：从杂乱的业务中提取高度抽象的公共基建（如动态表单引擎、高阶业务 SDK），API 设计必须具备极强的向前兼容性，且被 3 个以上其他业务线平滑接入。
*   **多端/跨栈思维**：在 Web、H5、跨端框架（如 RN/Taro/小程序）中游刃有余，能处理不同端底层的通信差异与渲染差异。

### 2. 复杂问题解决
*   **外科手术式重构**：接手历史“面条代码”时，能在不改变业务逻辑的前提下，抽离出纯净的视图层与独立的领域逻辑层（Custom Hook / Store）。
*   **源码级排障**：能从 V8 引擎的渲染管线、内存分配（GC）角度排查线上内存泄漏或掉帧。当第三方库出现 Bug 时，能直接 Fork 源码定位缺陷并出具 Patch，不被外部依赖阻塞。

### 3. 协作与软素质（硬性要求）
*   **技术边界防御（敢于说不）**：面对产品违背交互规范的需求，或后端要求前端写死极不合理的兼容逻辑时，必须能从技术成本角度当面驳回，并推动替代方案落地。
*   **技术方案主导**：对于超过 5 人日的需求，必须在编码前输出包含组件拆分、状态流转和接口定义的技术方案文档（Tech Spec），并组织 TL 进行评审。
*   **自动化沉淀**：能针对业务线痛点，编写脚本、自定义 Lint 规则或 CI/CD 流程，将团队的低效劳动时间压缩 20% 以上。

### ❌ 淘汰红线（Anti-patterns）
*   **鸵鸟心态**：看到身边的烂代码或明显的架构隐患（如某接口响应长达 3 秒），不仅不修复，还在上面继续叠加 `if-else`。
*   **故障无闭环**：线上出现 Bug 止损后，没有沉淀出防止同类问题再次发生的自动化测试用例或 Lint 拦截规则。
*   **沟通黑洞**：在跨部门联调中，习惯于“甩锅”（“这是后端接口慢/这是产品没说清楚”），而不是主动牵头拉会解决问题。

## P4：高级（系统级杠杆与领域权威）
**【晋升预期：P3-3 升 P4 需 1-2 年】**
**核心底线：系统底盘的构建者和跨团队的效能发动机，对线上崩溃买单。**

### 1. 技术与架构深度
*   **【P4-1】防腐层与平滑演进**：主导核心业务链路的推翻重写或技术栈整体跃迁。在此过程中，必须设计坚如磐石的防腐层（ACL），保证底层技术更迭对上层业务 100% 透明，且重构期间老业务 0 故障。
*   **【P4-2】工程基础设施**：从零构建支撑百人规模研发的底层基建（如脚手架、构建链路底层魔改、全链路监控大盘）。能编写自定义 Babel/Vite 插件，从编译时解决运行时的性能或兼容灾难。
*   **【P4-3】领域硬核破局**：在前端某一子领域（如 RN 跨端渲染引擎深度调优、Node.js 底层与内存溢出分析、WebAssembly）达到业界一线水平。

### 2. 复杂问题解决
*   **全链路追踪**：作为所有线上 P0 灾难的终结者。能迅速穿透前端网关、BFF 层直达底层微服务，完成全链路追踪、止损并主导复盘定责。
*   **自动化重构兵器**：熟练运用 AST、Codemod 等底层工具，或深度整合大模型能力，实现万行级别老旧代码的安全迁移和全量重构。

### 3. 协作与软素质（硬性要求）
*   **技术反推业务（Owner 意识）**：不再被动承接需求，而是直接对齐核心业务指标（如交易转化率、首屏留存率）。独立倒推需要做哪些 SSR 改造、体验优化，拿真实的业务增量数据说话。
*   **推行力与跨团队压制**：制定覆盖全团队的代码范式与架构契约。做出的基建，在业务线的接入率必须达到 80% 以上。能用极具说服力的技术方案推翻产品或后端的错误系统顶层设计。
*   **导师与技术布道**：必须带领和培养至少 2-3 名 P3 骨干，并在团队内/外部主导高质量的技术分享，建立自己的技术威望。

### ❌ 淘汰红线（Anti-patterns）
*   **脱离群众的架构（自嗨）**：沉迷于造轮子，搞出极其复杂、只有自己能看懂、业务线苦不堪言且无法落地的“空中楼阁”基建。
*   **技术债制造机**：为了抢进度，在核心系统里埋下只有自己知道的“定时炸弹”，导致团队后续维护成本剧增。
*   **护城河心态**：把核心代码或打包权限捏在自己手里，不愿意做知识转移，试图以此绑定自己在团队的地位。

## P5：架构师及前端负责人（规则制定与生态构建）
**核心底线：用技术战略定义公司未来的产研边界，打造不依赖个体的自治型高能组织。**

### 1. 技术顶层战略
*   **架构独裁权与 ROI 演算**：掌握团队技术栈的生杀大权。任何新框架、新范式的引入必须经过严格的商业 ROI 与维护成本演算。敢于在全行业追捧新技术时保持战略定力，也敢于在历史包袱极重时果断发起底座革命。
*   **绝对单一事实源**：强力摧毁各业务线之间的“信息孤岛”和“重复造轮子”。统一全公司的前端交互规范、数据契约与基础设施底座。

### 2. 组织机制与生态
*   **自治机制建设**：搭建包括技术评审（RFC）、质量红线、容灾演练在内的自运转系统，让高水平交付成为流水线的必然产物，而非个人英雄主义的偶然。即使自己休假，团队质量也不会出现丝毫降级。
*   **开发生态跨代演进（AI 融入链路）**：主导将自动化编码、智能单测生成、甚至是基于模型的设计图转代码（D2C）工具链深度嵌入公司研发骨干网，从根本上重塑 30 人团队的交付效率周期。

### 3. 协作与软素质（硬性要求）
*   **商业对话能力**：能够使用 CEO/业务一号位听得懂的语言，汇报技术团队的产出与瓶颈。把“编译速度提升”转化为“人效成本节约”，把“首屏优化”转化为“用户留存与转化收益”。
*   **人才梯队收放**：不仅能招募高标准的架构师，还要敢于对团队进行组织级重构。对于长期霸占坑位但不产出价值的“老白兔”，有雷霆手腕进行汰换。

### ❌ 淘汰红线（Anti-patterns）
*   **屁股决定脑袋**：过度保护前端团队的利益，在产研冲突中一味护短，而不是从公司整体大局（业务成败）出发解决问题。
*   **一言堂与技术独裁**：听不进一线核心骨干的技术建议，依靠职级强压不合理的技术方案。
*   **管理失控**：团队核心人才流失率高，出现严重的梯队断层（只有 P2 和自己，没有能打硬仗的 P3/P4）。
