# Sentry 环境区分与稳定性治理

## 核心定位

不是只看“有没有报错”，而是按环境、版本和场景建立稳定性基线。

## 关键动作

- 按开发、测试、预发、生产区分监控环境。
- 按版本打 release 标记。
- 先建立崩溃率基线，再做对比。
- APP 体验问题从崩溃率起步，再看白屏、卡顿、启动耗时。
- 结合 AppState、breadcrumbs 和关键链路定位问题。

## 评估维度

- 各环境崩溃率
- crash-free session
- 新增问题数
- 回归问题数
- 发现到定位耗时
- 发版后回退率

## 落地顺序

1. 环境隔离
2. 基线建立
3. 发版对比
4. 告警和聚合规则
5. 复盘和修正

## 结论

稳定性治理的关键不是“报错少一点”，而是“每次变化都能比较、定位和复盘”。
