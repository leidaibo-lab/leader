# 对话共识到 Skill 的主动收录规则

## 使用场景

当用户和 Agent 在当前项目中讨论规划、架构、管理方法论、AI 治理、组织机制或可复用表达时，如果讨论中形成了稳定共识，Agent 应主动判断是否建议录入对应 Skill。

## 核心原则

主动收录不是把所有聊天记录保存下来，而是把已经被用户认可、后续可复用、能减少重复沟通的信息，沉淀为项目内可维护的 Skill 资产。

## 建议录入条件

满足以下任一条件时，Agent 应在回复中增加“建议录入”清单：

- 用户明确表示认可，例如“这次理解正确”“我很满意”“可行”“这个落地到规划中”。
- 讨论形成了新的稳定判断、方法论、架构层级、角色边界或表达口径。
- 用户多次纠偏后，最终收敛出更准确的说法。
- 内容能被未来相似问题复用，且不依赖当前一次性上下文。
- 内容能减少后续重复解释、重复沟通或重复产出。

## 建议录入内容

优先录入：

- 已被用户认可的核心判断。
- 可复用的方法论、流程、治理规则和判断标准。
- 角色定位、职责边界、表达禁区和稳妥表达。
- 架构层级变化、流程节点变化和指标口径变化。
- 可作为后续输出模板的句式、清单和结构。

不录入：

- 临时草稿、被用户否定的结构和中间试错版本。
- 浏览器状态、临时文件路径、截图路径和一次性执行过程。
- 尚未确认的猜测、未经验证的外部事实和短期时效信息。
- 只服务当前回复、未来复用价值很低的措辞。

## 执行流程

```text
识别候选共识
→ 在回复中列出“建议录入”
→ 等用户确认
→ 判断归属 Skill
→ 写入对应 SKILL.md 或 references
→ 同步更新 README.md / AGENTS.md 路由
→ 用 git diff 复核变更范围
```

## 输出格式

当需要提示用户确认时，使用简洁格式：

```text
建议录入：
- <候选共识 1>：建议沉淀到 <Skill / reference>
- <候选共识 2>：建议沉淀到 <Skill / reference>
```

当用户已经明确确认“可行”“落地”“写入”时，可以直接执行，但仍需在最终回复中说明写入位置。

## 归属判断

- 前端负责人角色成长、组织机制、管理方法论：归入 `frontend-leadership/frontend-leader`。
- 技术架构、AI 效能、AI 治理、质量反推、稳定性治理：归入 `frontend-leadership/tech-efficiency-architect`。
- 组织架构、业务线划分、向上汇报和公司交付视角：归入 `frontend-leadership/org-architect`。
- 招聘、绩效、人才梯队、人员稳定性：归入 `frontend-leadership/people-culture-manager`。
- Skill 规则、目录规范、对话共识沉淀机制：归入 `company-public/skill-governance`。

## 固定口径

> 规划、架构、管理方法论类讨论中，Agent 应主动识别已被用户认可的共识、判断、表达口径和架构变化，并在回复中给出“建议录入”清单；用户确认后，再写入对应 Skill。
